# 1.0.1 patch judgments

| patch | judgment | reason |
|---|---|---|
| `dist/core/agent-session.js` | **re-cut** | `session-state`: retry fields now carry `_failedResponse` docs after them. `agent-event-boundary`: comment text changed. `post-run-stop`: 1.0 tracks tool results and `_failedResponse`, and `!message` now returns `hasQueuedMessages()`; ours interleaves the stop-continuation checks into that body. `abort-entry`: 1.0 marks `_abortDuringBeforeSettle`; kept, and set whether or not the agent request is aborted. |

| other 3 | keep | anchors intact. |

Semantic break found and fixed: 1.0's run loop skips `_handlePostAgentRun` once
`_agentRunAbortRequested` is set, so a stop armed by an abort that joined the run's `agent_end`
boundary was never consumed and silently cancelled the next run's first retry (the test hung in
its retry-gap phase). New sub-patch `run-scoped-stop` consumes it in the run's `finally`.
Test: `abort-provenance.test.mjs` 2/2 (late-boundary abort followed by the retry-gap phase).
