# 0.86.1 → 1.0.1 패치 재판정

대조 원본은 pristine 0.86.1 설치본이고, `preimageSha256`과 `version`(`PI_VERSION`)은
중앙에서 다시 기록됐다. 업스트림이 같은 일을 하게 된 단계는 없다(delete 0).

| 패치 | 판정 | 사유 |
|---|---|---|
| `dist/api/anthropic-messages.js` (pi-ai) | re-cut | `convert-messages-model`/`convert-messages-helpers`가 죽었다. 1.0.1은 대화 중 추가 도구를 `tool_addition` 안에 정의째(inline) 싣고, 그래서 `convertMessages`의 여섯째 인자가 `nativeToolChanges` 불리언에서 도구 정의 변환 함수(`convertToolDefinitions`, 네이티브가 아니면 `undefined`)로 바뀌었다. 호출부와 시그니처 둘 다 그 뒤에 `model`을 덧붙인다. providerNative 블록 시작/델타/정지와 replay 하위 패치는 그대로 붙는다. |
| `dist/api/openai-responses-shared.js` (pi-ai) | keep | 앵커 그대로. |
| `dist/types.d.ts` (pi-ai) | keep | 앵커 그대로. |

## 설치 레이아웃 (앵커가 아닌 의미 깨짐)

0.86.1은 pi-ai/pi-tui를 `pi-coding-agent/node_modules` 아래 두었고 1.0.1은 형제로 hoist한다.
`src/host-sdk.mjs`가 중첩 경로를 박아서 staged SDK 테스트가 모듈 로드에서 죽었다. 이제
coding-agent 엔트리에서 `findPackageJSON`으로 pi-ai/pi-tui를 찾는다(coding agent 자신과
같은 해석, 두 레이아웃 모두). `native-media.test.mjs`는 `resolvePiRuntime`으로 pi-ai를 찾는다.
`compat`의 `generateImages`/`getImagesApiProvider`/`registerImagesApiProvider`와
`StringEnum`은 1.0.1에서도 `export *`로 그대로 나온다(0.99 이미지 API 변경과 무관).

## 테스트

`node --test features/media-tools/*.test.mjs` — 결과는 report 참조. hoist 레이아웃 고정은
기존 "staged stock SDK executes webfetch, look_at, and client generate_image" 테스트가 맡는다
(수정 전 `ERR_MODULE_NOT_FOUND`로 실패).
