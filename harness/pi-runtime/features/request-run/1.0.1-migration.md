# 1.0.1 patch judgments

| patch | judgment | reason |
|---|---|---|
| `dist/core/agent-session.js` | **re-cut** | `event-observer`: `_handleAgentEvent` now starts with nested-call bookkeeping. `submit-record`: follows input-lifecycle's de-indented prompt. `settled-terminal`: see below. |

| other 4 | keep | anchors intact. |

Semantic break found and fixed (`settled-terminal`): clients (T3, the engine, a session-link
sender) read an announced `agent_settled` as "the work is done". 0.86 started a wake's run inside
the settle handler and skipped the stale announcement. 0.87 defers runs requested during the
dispatch until all handlers return, so stock announced the first run's settle and then started
the next run: a session-link sender heard "done" before its message was answered. The patch now
holds the announcement while deferred work is pending and makes it afterwards only if that work
started no run.
Tests: `request-run.test.mjs` "a prompt sent while an extension holds agent_settled starts after it,
and only the last run's settle is announced"; `session-link-runtime.test.mjs` "a delivery during a
run that ends normally (...)" x4 (`streamingAtSettle` stays `[false]`).
