# 1.0.1 patch judgments

0.99 added a native exposure model (`direct | model-only | codemode | deferred | hidden`) and a
built-in `tool_search`. Ours stays (intent non-goal: no swap); stock-defaults keeps the built-in off.

| patch | judgment | reason |
|---|---|---|
| `core/extensions/types.d.ts` | **re-cut** | `exposure-type` no longer redeclares `ToolExposure`; it adds `"search"` to 1.0's union. `definition-fields` drops our `exposure` field (1.0 declares it). `tool-info` follows 1.0's `ToolInfo` (namespace, annotations). |
| `core/agent-session.js` | **re-cut** | 1.0 funnels both auto-activation paths (all extension tools at startup, tools new to a refresh) through `_isActivatedOnRegistration`, so the surface policy hooks there (`registration-direct-only`) instead of the three 0.86 sub-patches. Explicitly named tools still activate. `catalog-metadata` keeps 1.0's namespace/annotations and overrides `exposure` with ours (only the disabled built-ins read 1.0's value). |
| `core/extensions/index.d.ts`, `index.d.ts` | **re-cut** | `ToolExposure` is already exported by 1.0; export only `normalizeToolExposure`. |
| other 3 | keep | anchors intact. |

At runtime 1.0 treats `search` as not declarable on registration and not callable through native
`ctx.executeTool`; both match our intent while the built-ins are off.
Tests: `tool-search.test.mjs` 2/2 (direct set starts active, others wait; staged MCP discovery and same-turn call).
