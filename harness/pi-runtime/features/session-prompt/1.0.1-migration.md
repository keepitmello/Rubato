# 1.0.1 patch judgments

| patch | judgment | reason |
|---|---|---|
| `core/extensions/runner.js` | keep + **new sub-patch** | `runner-emit-system-prompt` intact. New `context-system-slots`, below. |
| `core/agent-session.js` | **re-cut**, part **delete** | `compose-method`: the transcript-restore doc comment is now multi-line. `before-run`: `_runAgentPrompt` gained selection/failed-response bookkeeping above the `try`. `projection-*`, `system-prompt-getter` intact. The three `deferred-custom-*` sub-patches are **deleted**: since 0.87 every request is built from the SessionManager projection and stock's `turn_end` flush appends held custom messages to the session, so the next request of the same run already carries them right after the latest tool results. |

New sub-patch (audit finding 1, cache prefix): 0.87 hides system messages from `context` handlers
and, when a handler changes the conversation, replaces every system message with one replayed
head that carries the current prompt and all current tools. Rubato's handlers (tool-output
previews, history-notes markers, image limits, codemode hint) change messages on most requests,
so a tool loaded mid-session by tool_search moved into the leading tool list and the provider
prefix changed from token 0. `restoreSystemMessages` now puts each system message back before
the conversation message it preceded (identity, or position for a same-length rewrite); only a
reordering handler falls back to stock.

Tests: `session-prompt.test.mjs` (3): held custom message lands once right after the tool result
in the same run and stays put next run; a mid-session tool declaration stays in place after a
same-length rewrite and after an insert-plus-drop. The last two fail with the sub-patch removed.
