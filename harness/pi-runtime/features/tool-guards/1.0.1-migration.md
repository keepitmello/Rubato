# 0.86.1 → 1.0.1 재판정

이 feature는 엔진 패치가 없다(`patches: []`). 그래서 앵커가 죽은 곳은 없고, 깨진 건
런타임 코드의 의미 하나다(감사 helper finding #2).

| 대상 | 판정 | 사유 |
|---|---|---|
| `demote-unavailable.mjs` | 수정 | pi-ai 1.0.1(`inline-tools-2026-09-15`)은 Anthropic top-level `tools`를 첫 도구 + `__pi_deferred_placeholder__`로 고정하고, 나중에 로드된 도구는 메시지 안 `{type:"tool_addition", tool:{type:"tool_definition", definition}}`로 정의째 싣는다. 0.86.1은 같은 도구를 top-level에도 `defer_loading`으로 나열했다. demote는 top-level만 "정의됨"으로 봤으므로, 1.0.1에선 tool_search로 중간에 로드된 도구의 호출과 결과가 전부 `<unavailable-tool-call>`로 바뀌었다(동작 깨짐 + 그 턴부터 캐시 prefix 변경). |
| `tool-pair.mjs`, `apply-patch.mjs`, `loop-guard.mjs` | keep | 변경 없음. apply_patch는 여전히 `setActiveTools`로 edit/write를 숨기고, 1.0.1에선 그게 transcript의 `toolsRemoved` → wire `tool_removal`이 된다. |

## 새 규칙

요청의 블록을 순서대로 걸으며 "그 시점에 정의된 이름" 집합을 유지한다.

```
top-level tools ─▶ 시작 집합
tool_addition (tool_definition: definition.name / tool_reference: name) ─▶ 추가
tool_removal  (tool_reference: name)                                   ─▶ 제거
tool_use ─▶ 그 시점 집합에도, 서버 tool_search 의 tool_reference 에도 없으면 demote
```

- OAuth: pi-ai가 정의(`convertTools`)·삭제·`tool_use` 이름을 모두 같은 `toClaudeCodeName`으로
  바꿔 싣으므로 wire 이름끼리 바로 비교하면 매핑이 맞는다(예: `grep` → `Grep`).
- apply_patch로 처음부터 숨긴 edit/write는 어디에도 정의가 없으니 계속 demote된다.
- 정의된 동안 한 호출은 나중에 `tool_removal`이 와도 그대로 둔다. 정의가 그 앞의
  `tool_addition`(또는 top-level)에 남아 있기 때문이고, 0.86.1에서도 지워진 도구는 top-level에
  남아 demote되지 않았다(동작 동일). 삭제 뒤에 한 호출만 demote된다.
- 서버 tool_search가 낸 `tool_reference`(tool_result 안)의 dangling 판정은 "요청 어디서든 한 번이라도
  정의된 이름" 기준이다.
- demote 안내 문구의 도구 목록은 top-level 중 `defer_loading`이 아닌 것만 쓴다. 이 문구는 demote된
  history에 구워지므로 도구가 중간에 로드돼도 바뀌면 안 되고(캐시 prefix), placeholder는 모델이
  부를 수 있는 도구가 아니다. 0.86.1 세션의 문구는 엔진 교체 때 한 번 바뀐다(이미 top-level 목록이
  바뀌는 시점이라 추가 비용 없음).
