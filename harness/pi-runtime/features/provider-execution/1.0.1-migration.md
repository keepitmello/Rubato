# 0.86.1 → 1.0.1 패치 재판정

엔진 핀을 1.0.1로 올리며 이 feature의 깨진 패치를 판정했다. 대조 원본은 pristine 0.86.1
설치본이고, `preimageSha256`과 `version`(`PI_VERSION`)은 중앙에서 다시 기록됐다.

4개 패치 모두 앵커가 죽었고, 넷 다 re-cut이다. 업스트림이 같은 일을 하게 된 단계는 없다.

| 패치 | 판정 | 사유 |
|---|---|---|
| `dist/core/sdk.js` | re-cut | 1.0.1은 `let agent;`를 없애고 `buildRequestOptions` 뒤에서 `const agent = new Agent(...)`를 만든다. `let session;`을 `buildRequestOptions` 바로 앞에 건다. 그 안의 `providerExecuteTool`/`providerExecCwd`/`providerExecAgentDir`/`providerExecLineageId` 주입과 `session = new AgentSession` 대입은 그대로 붙는다. |
| `dist/agent-loop.js` (agent-core) | re-cut | 두 군데가 바뀌었다. (1) 에러/abort 종료 때 1.0.1은 `lastCompletedTurn`을 만들고 `finishTurn`을 부른 뒤 `turn_end`를 낸다. provider가 실행한 결과를 먼저 짝지어 붙이는 우리 흐름에 그 두 줄을 그대로 얹고, `finishTurn`과 `turn_end` 둘 다 provider 결과를 받게 했다. (2) `streamFunction` 호출 뒤에 `result()` 래퍼(요청한 thinking level 기록)가 끼었다. 앵커를 호출에서 끊어 래퍼는 stock 그대로 둔다. `streamAssistantResponse` 호출처는 여전히 하나라 반환형 변경은 안전하다. |
| `dist/core/extensions/runner.js` | re-cut | `emitToolResult` 반환에 `structuredContent`가 끼었다. `addedToolNames`를 그 뒤에 싣는다. |
| `dist/core/agent-session.js` | re-cut | afterToolCall 본문이 `AgentSession._afterToolCall` 메서드로 빠지고 들여쓰기와 `structuredContent`가 바뀌었다. 이 메서드는 모델 호출과 `ctx.executeTool()` 중첩 호출이 같이 쓰므로, 둘 다 `addedToolNames`를 전달한다. |

## `addedToolNames`와 1.0.1의 inline 도구 정의

리드 단서: 0.99가 도구 노출/`prepareLoadout`/`ctx.executeTool`을 바꿨고, 1.0.1은
Anthropic 대화 중 추가 도구를 `tool_addition` 블록 안에 정의째(inline) 싣는다.

확인 결과: `addedToolNames`는 여전히 provider 요청에 실리지 않는 우리 둘 사이의 전달
필드다(`tool-execution/runtime.mjs`가 쓰고 `cursor-exec-bridge.mjs`가 읽는다). 시스템
프롬프트·도구 스키마·초기 메시지 어디에도 닿지 않으니 캐시 prefix와 무관하다. 1.0.1의
inline 정의는 요청 레벨 도구 목록을 첫 요청 그대로 고정하므로 prefix를 오히려 지킨다.
0.86.1 각주의 keep 판단(업스트림 `toolsAdded`로 갈아타기는 별도 후속)은 그대로다.
