`harness/pi-runtime/node_modules` (pristine; siblings hoisted). Old-side oracle:
the pristine 0.86.1 install. Each broken anchor was read next to what changed
around it. Preimage hashes and `version` (`PI_VERSION`) were re-recorded centrally.

## Install layout (semantic break, not an anchor)

0.86.1's shrinkwrap nested pi-ai under `pi-coding-agent/node_modules`; 1.0.1
hoists it to `node_modules/@earendil-works/pi-ai`. Three owned files assumed
the nested layout and failed only at runtime:

| file | fix |
|---|---|
| `auth-pool/coding-agent-runtime-pool.mjs` | re-exports pi-ai's pool from `import.meta.resolve("@earendil-works/pi-ai")`, so the coding-agent copy and pi-ai share one module instance in either layout. |
| `engine-paths.mjs` (`senpiDir`, used by `credential-import`) | finds the coding-agent package as the nested owner or the hoisted sibling (manifest name check) instead of `piAiRoot/../../..`. Pinned by `engine-paths.test.mjs` (both layouts). |
| `astra-codex.test.mjs` | reads stock pi-ai from whichever layout exists. |

Vendored Cursor files import `calculateCost`, `createProvider`,
`registerSessionResourceCleanup`, `providerHeadersToRecord`, `parseJsonWithRepair`,
`parseStreamingJson`, `sanitizeSurrogates`, `lazyOAuth`; all still exported by 1.0.1.
