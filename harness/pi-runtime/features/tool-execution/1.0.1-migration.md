# 1.0.1 patch judgments

Judged against the installed `@earendil-works/pi-coding-agent` 1.0.1; old side is pristine 0.86.1.
1.0.1 adds its own `ctx.executeTool()` for tool contexts (nested calls with `parentToolCallId`).
It lives on `contextActions`/`runner.executeToolFn`; ours is `pi.executeTool` on `actions`, so the
two do not overwrite each other. Ours stays: it adds lazy activation and caller-supplied call ids
that codemode and the Cursor bridge use. `delete` count: 0.

| patch | judgment | reason |
|---|---|---|
| `core/extensions/types.d.ts` | **re-cut** | `runtime-state` anchor died: 0.99 put `pendingVirtualModelRegistrations` between the native-provider queue and `assertActive`. Our fields now go right before `assertActive`. `ExecuteToolOptions` merges with 1.0's interface of the same name. |
| `core/extensions/loader.js` | **re-cut** | `runtime-lazy`: `mcpServers` now follows `pendingNativeProviderRegistrations: []`. |
| `core/agent-session.js` | **re-cut** | `activator-field`: `_nestedToolCalls`/`_hiddenDeclarations` now follow `_toolRegistry`. `single-editor`: `setActiveToolsByName` became a wrapper; every loadout (it, transcript restore, the per-request loadout) now funnels through `_applyToolLoadout`, so the apply_patch filter moved there. |
| `core/agent-session.d.ts` | **re-cut** | `field`: same neighbour change as the runtime. |
| `index.d.ts` | **re-cut** | `type-export`: the root type list now starts `AfterProviderResponseEvent, AgentActivityOutcome`. |
| other 5 | keep | anchors intact. |

Semantic change taken on (audit finding 4): 0.99's agent loop honors a returned `{ isError: true }`
(stock bash returns it on a non-zero exit; our PTY bash and eval cells always did). `runtime.mjs`
now reports the same through `pi.executeTool`, so a nested call agrees with a direct one.
Test: `tool-execution.test.mjs` "a tool that returns isError without throwing is an error through executeTool too".
