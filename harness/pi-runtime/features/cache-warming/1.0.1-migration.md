# 0.86.1 → 1.0.1 패치 재판정

intent `pi-1-0-upgrade` revision 1. 대조 원본: 0.86.1·1.0.1 npm 설치본(pristine).
`preimageSha256`과 `version`(PI_VERSION import)은 porter가 1.0.1로 다시 기록했다. 앵커는 하위 패치 18개 모두 그대로 붙는다.

| 패치 | 판정 | 사유 |
|---|---|---|
| `core/cache-warmer.js` start-ttl | re-cut (의미) | 0.87.0이 "타이머가 늦으면 만료된 캐시를 다시 쓰는" 문제를 고치며 `schedule()`에 `refreshDeadlineAt = nextWarmAt + floor((ttlMs - delayMs) / 2)`를 넣었다. `refresh()`는 이 시각을 넘기면 "cache refresh deadline missed"로 멈춘다. 우리는 `ttlMs`에 간격(40m/20m)을 넘겨 `ttl == delay`였고, 여유가 0이 됐다. unref된 타이머는 거의 항상 1ms 이상 늦으므로 첫 예열에서 warmer가 멈췄다. 유휴 세션 예열이 소리 없이 죽는다. 이제 `ttlMs`에 실제 캐시 수명(`RUBATO_CACHE_LIFETIME_MS`: Anthropic 1h, Codex 30m)을 넘긴다. 늦은 타이머의 여유는 Claude 10분, Codex 5분이다. |
| start-delay | keep | `delayMs`는 그대로 간격(`RUBATO_WARMING_INTERVAL_MS`)이다. |
| start-anchor / settled-deadline / schedule-deadline / schedule-first-touch (`anchoredUntil`) | keep | 마지막 user 입력 뒤 N시간 지평 로직은 그대로다. stock 마감 줄은 우리 `nextWarmAt` 계산 뒤에 오므로 고정된 시각 기준으로 잡힌다. |
| 나머지 (status-until, policy, replayable, refresh-compaction, refresh, session-mode, start-held, session-switch, economics, settings-default, rpc-commands) | keep | 앵커가 그대로이고, 기존 테스트 10개가 동작을 잡는다. 이번에는 마감 문제만 의미까지 따졌다. |

수명 상수의 정본 자리: 레포 전체에서 쓰는 Anthropic·Codex 캐시 수명 상수는 없다.
statusline은 Codex를 opaque로 다루고, pi-ai 모델 데이터에는 Anthropic `promptCache`가 없다.
그래서 간격 표 바로 옆, 이 패치의 policy 블록에 둔다.

## 테스트

`node --test features/cache-warming/*.test.mjs` → 12/12 통과.
- 새 테스트 "<provider>: a timer that fires late still warms within N minutes, and stops after"(anthropic 10분, openai-codex 5분):
  +5초 늦은 타이머는 예열하고, 정확히 N분 늦으면 아직 예열하고, N분 + 1ms 늦으면 "cache refresh deadline missed"로 멈춘다.
  고치기 전 패치로 돌리면 +5초에서 예열 0회로 실패한다.
- "a session picks how many hours…"는 고치기 전에는 예열 0회로 실패했고 이제 통과한다.
  `advance()`가 시계를 한 번에 옮겨 타이머가 10분 늦은 것과 같았다.
- "a shorter window than the time already passed ends warming": `advance(70분)` 한 번을 `advance(40분)` + `advance(30분)`으로 나눴다.
  한 번에 옮기면 40분 타이머가 30분 늦게 발사된다. 1.0은 그런 늦은 예열을 일부러 버린다(새 테스트의 미스 경계).
  이 테스트가 보는 것은 창을 1시간으로 줄이면 끝난다는 점이고, 예열 1회는 준비 단계일 뿐이다.
- 경로: pi-ai 위치를 `runtime.packages[...].dir`로 바꿨다(Phase 3).
