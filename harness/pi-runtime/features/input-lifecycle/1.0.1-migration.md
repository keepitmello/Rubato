# 1.0.1 patch judgments

1.0.1 (0.99) added its own per-input disposition for RPC responses (`preflightResult("handled" |
"queued" | "started")`, `steer()`/`followUp()` return values). Ours is different: one input id at
admission, the `input_disposition` extension event and queued-message identity. Both stay.

| patch | judgment | reason |
|---|---|---|
| `dist/core/agent-session.js` | **re-cut** | `prompt()` lost its preflight try/catch (RPC now reports a thrown prompt itself), gained the `agent_settled` deferral head, and is de-indented. Our own try now spans the body; `inputStarted` keeps a failure after "started" from being reported as "rejected", exactly like the old preflight scope. Queued/handled/started anchors follow the new `preflightResult` values; `_queueUserInput` returns the disposition 1.0 expects; `_queueFollowUp` pushes a one-line object now. The old `prompt-rejected` sub-patch is folded into `prompt-started`. |
| other 5 | keep | anchors intact. |

Tests: `input-lifecycle.test.mjs` 2/2 (covers handled, rejected, started, steer and follow-up identity on the real SDK).
The scratch copy now links the hoisted `node_modules` too: 1.0.1 ships no shrinkwrap.
