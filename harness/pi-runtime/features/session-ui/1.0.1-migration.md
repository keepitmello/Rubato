# 0.86.1 → 1.0.1 패치 재판정

intent `pi-1-0-upgrade` revision 1. 대조 원본: 0.86.1·1.0.1 npm 설치본(pristine).
`preimageSha256`과 `version`(PI_VERSION import)은 porter가 1.0.1로 다시 기록했다.

| 패치 | 판정 | 사유 |
|---|---|---|
| `dist/core/model-runtime.js` | re-cut | pi-ai import 줄 앞에 `clampThinkingLevel`이 붙어 `import { createModels,` 앵커가 죽었다. `defaultProviderAuthContext`는 ` createModels, lazyStream,` 앞에 넣는다. pi-ai `auth/context.js`는 0.86.1과 바이트 단위로 같고, `createModels({ authContext })`와 `prepareRequest`의 `options.env` 병합도 그대로다. |
| `dist/modes/interactive/theme/theme.js` | re-cut (의미) | 앵커는 붙지만 1.0이 터미널이 보고한 색을 모듈 전역 `terminalColors`·`terminalColorsPending`·`terminalColorScheme`에 둔다(OSC 10/11/4 응답, mode 2031). hosted 프레젠테이션마다 터미널이 다르니, 다른 테마 전역처럼 `uiState()`로 옮겼다. 안 옮기면 한 터미널의 색과 밝기 판정이 다른 터미널의 테마로 샌다. 터미널 입력은 `scope.run` 안에서 들어오므로(pi-server `terminal-process.mjs`) 답장도 해당 세션 상태에 쓰인다. |
| pi-tui `keys.js`·`terminal.js`·`keybindings.js`·`terminal-image.js` | re-cut (의미) | 앵커는 그대로지만 import 깊이가 틀렸다. 1.0.1 설치는 pi-tui를 `pi-coding-agent` 옆으로 hoist한다. 그래서 stage 루트의 `rubato-features/`까지는 7단계가 아니라 4단계다. 7단계로 두면 stage 밖을 가리켜 엔진이 모듈을 못 찾는다. 앵커 검사는 이걸 못 잡는다. |
| 나머지 22개 파일 | keep | 앵커가 전부 그대로다. 우리가 손대는 함수의 의미도 확인했다. `bindExtensions`는 끝에 `reportUnhandledMcpServers()`만 더했고, 우리 presentationOnly 조기 반환이 그 앞이라 두 번째 프레젠테이션이 MCP 경고를 다시 띄우지 않는다. interactive-mode의 `resetExtensionUI`·`showExtensionCustom`·메인 루프는 바뀌지 않았다. `process.exit(` 호출 자리 수는 interactive-mode·rpc-mode·main·file-processor 모두 0.86.1과 같다. 새 모듈 전역은 theme.js에만 있다. |

## 테스트

`node --test features/session-ui/*.test.mjs` → 4/4 통과.
- "real theme, keybindings…" 테스트가 pi-tui 경로를 중첩 배치로 박아 두었다.
  이제 stage된 런타임에서 `resolvePiRuntime`로 찾는다.
- 같은 테스트에 터미널 색 격리 단언을 더했다. 두 스코프에 다른 색과 scheme을 넣으면 `getTerminalTheme()`이
  `['dark','light']`로 갈리고, 스코프 밖 값은 그대로다. theme.js 범위 처리를 빼고 돌리면
  `['light','light']`로 실패하는 것을 확인했다.
- 깊이 오류는 기존 "two native InteractiveModes…" 테스트가 잡는다(고치기 전 ERR_MODULE_NOT_FOUND).

## 남은 위험

- pi-tui `wheel-scroll.js`(1.0 신규, fullscreen 전용)는 휠 가속 여부를 서버의 `process.env`·platform으로 정한다.
  0.86.1 `tui-alt-screen.js`도 서버 env를 읽었고 그때도 범위를 씌우지 않았으니 같은 성질이다.
  TUI 모드는 동결이라 기본 경로가 아니다.
