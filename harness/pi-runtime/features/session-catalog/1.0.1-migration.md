# 0.86.1 → 1.0.1 패치 재판정

intent `pi-1-0-upgrade` revision 1. 대조 원본: 0.86.1·1.0.1 npm 설치본(pristine).
`preimageSha256`과 `version`(PI_VERSION import)은 porter가 1.0.1로 다시 기록했다.

| 패치 | 판정 | 사유 |
|---|---|---|
| `session-manager.js` persist-first-user | delete | 1.0(#10000)이 `_hasConversation()`으로 user 또는 assistant 메시지가 생기는 순간 파일을 만든다. 우리가 걸던 규칙과 같다: 설정 엔트리만 있으면 메모리에만 두고, 첫 user 메시지에 전부 쓴다. `createBranchedSession`도 같은 규칙을 쓰게 됐다. |
| `session-manager.js` file-rollback-metadata-append | delete | 앵커였던 "assistant 전 + 이미 flush됨" 분기가 업스트림에서 사라졌다. 그 경로는 이제 `else` 분기 하나로 모이고, 그 분기는 아래 first-flush 패치가 `_appendLine`으로 바꾼다. 패치 후 `_persist`에 남는 raw `appendFileSync(this.sessionFile…)`는 `_appendLine` 안의 하나뿐이다. |
| `session-manager.js` file-rollback-imports / first-flush / append-rollback / catalog-import / paged-api | keep | 앵커가 그대로다. `listPage`/`listAllPage`가 쓰는 내부 함수(`readSessionHeaderForDiscovery`, `sessionCwdMatches`, `getSessionHeaderCwd`, `buildSessionInfo`, `getDefaultSessionDirPath`, `getSessionsDir`)의 시그니처도 바뀌지 않았다. 새 `appendContextEdit`도 `_appendEntry`를 거치므로 rollback이 그대로 걸린다. |
| `session-manager.d.ts` | keep | 1.0.1이 `ContextEditEntry`·projection 타입을 더했지만 우리 앵커(`SessionListProgress`, `list` 선언)는 그대로다. |

  1.0.1 설치는 그것들을 `pi-coding-agent/node_modules`가 아니라 바로 옆에 두기 때문이다.
  스크래치 루트에 그 `node_modules`도 링크했다.

  이제 업스트림 동작을 대상으로 잡는다.
