# 점검표 양식
- **연습 빠른 경로**: §1·2·3·6·7과 연습 결격 사유를 확인한다. 사용자 승인 시 실험 승인(PASS-PROBE)이며 레드팀·블라인드 리뷰·별도 `FRAME_LOCK`은 생략할 수 있다.
- **무대**: 전체 필수. §5 도입 경로를 포함하고 주최사 연결 사슬만 해당 없으면 `N/A + 이유`로 적는다. §9 제외.
- **실전**: 전체 + §9 부록.
작성 규칙과 좋은/나쁜 예는 `references/01-gate-fields.md`. 판정·상태 문자열과 전이는 `references/02-tiers-and-verdicts.md`가 정본.
제안 출처 토큰 정본: `HUMAN_SEED` / `AI_PROPOSED` → `USER_ADOPTED` | `USER_MODIFIED` | `USER_REJECTED` (축약 표기: `(seed)`, `(AI제안→채택)`, `(AI제안→수정)`, `(AI제안→기각)`). 사용자 채택은 제안 출처 상태만 바꾼다 — 증거 등급은 그대로다(채택돼도 E0는 E0). 논쟁이 있었던 기각 제안은 이유 한 줄을 §8에 남긴다.
