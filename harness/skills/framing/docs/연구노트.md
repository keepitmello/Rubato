# framing·reframing 연구노트

> 스킬을 만들고 고치면서 얻은 고찰의 누적 문서. 세션마다 날짜 섹션을 추가한다. SKILL.md에서 참조하지 않으며 실행 세션에 로드되지 않는다 — 사람과 다음 연구 세션이 읽는다.

## 2026-08-04 — 탄생 세션

### 계기

KB 해커톤(2026-08-02~03, 15시간 스프린트)에서 "왜 만드는가"가 구현 중에 흐려져 가치 정리가 마감 2시간 반 전에야 나왔다. 복기 포렌식으로 회귀 케이스를 만들고(작성자 로컬: `~/.claude/roo-channel/notes/kb-회귀케이스.md`), 그 채점표를 통과하도록 framing을 설계했다. reframing은 같은 해커톤에서 "치매 진단" 매몰을 외부인의 "so what?" 질문이 깨준 사건을 일반화한 것.

### 회귀 기준 축소 결정

회귀 케이스의 "잡아야 할 실수" 7종 중 3종(REG-04·05·06 — 제출물의 주장과 코드의 간극, 재현 안내 부실)은 **프로토타입을 내는 판에서 결함이 아니라는 결정으로 제외**했다. 유효 기준 4종: 문서 간 결정 권위 분열 / 부분 동결 상태 착수(스캐폴딩은 허용이 정답) / 재정의 시 재점검 없이 구현 / 스스로 정한 주장 수위를 스스로 넘음. 마지막 것이 가장 정당한 검사다 — 외부 기준이 아니라 자기 일관성이라 판의 조건과 무관하게 항상 검사 가능.

### 설계 결정과 논리

- **쌍 구조**: framing=수렴(좁히고 동결), reframing=발산(경계 자체를 의심). framing 안의 발산 역할은 결정 경계 안에서 후보를 넓히는 것이고, reframing은 경계 밖 탈출 — 후보를 아무리 넓혀도 다 비슷하면 넘어갈 때다.
- **reframing은 단계가 아니라 비상구**: 프레임이 이미 있어야 돌릴 수 있고(re-의 의미), 잘 풀리는 판은 framing 혼자 끝나는 게 정상. 자주 불리면 프레임을 얕게 잡는다는 신호.
- **매몰은 구조 문제**: 프레임을 다듬은 세션은 애착이 생겨 스스로 못 빠져나온다. 감지는 메인, 수행은 블라인드 독립 세션 — 레드팀 독립 요건과 같은 논리, 방향만 반대(레드팀=부수기, reframing=잇기).
- **새 프레임은 무에서 안 나온다**: KB의 답은 "이미 있는 진단 인프라와 보험상품을 잇는 다리"였다. 브릿지 리서치가 스킬의 손발인 이유.
- **위임은 능력 계약이 정본**: 처음엔 특정 모델 삼총사(Fable·Codex·GPT-5.6 Pro)로 박았다가, 공유 가능성 때문에 "독립 시각 생성/외부 리서치/내부 조사"라는 역할을 정본으로 하고 모델명은 작성 환경 권장 매핑으로 내렸다.

### 용어 교훈 (두 번 실패 후 확정)

1차 번역투("즉시 탈락 조건", "출품판"), 2차 시적 신조어("닿는 길", "그 순간") 둘 다 기각. 확정 기준: **실무자가 회의에서 실제 입에 올리는 말** — 외래어는 외래어로(트리거·스코프·레드팀·메커니즘), 정착 번역어는 그것으로(불변식·결격 사유·동결). 실패 축은 "우리말이냐"가 아니라 "실제로 쓰는 말이냐 지어낸 말이냐".

### 리뷰에서 얻은 일반 교훈

- **정본 중복이 충돌의 뿌리**: 독립 리뷰(Codex sol high)가 찾은 결함 8건 대부분이 같은 규칙을 SKILL·reference·template에 반복해서 생긴 불일치였다. 이후 "정본 지도" 명시로 대응. 문서 시스템을 만들 때 반복 서술은 편의가 아니라 미래의 충돌이다.
- **적대 리뷰와 건설 리뷰의 동시 위임 기준**: 지적이 검증형(토큰 불일치·깨진 참조 — 대조하면 나오는 사실)이면 한 세션에 섹션만 분리해서 맡겨도 된다. 판단형(설계·프레임 자체 공격)이면 자세가 출력을 바꾸므로 세션을 나누고, 나눌 땐 같은 모델 둘보다 다른 계열 둘. 한 세션에 둘 다 시켜야 하면 적대 먼저(애착 형성 전).

### 동생 측 run-challenge와의 비교 (2026-08-04 시점 설계안)

거의 완벽한 상호보완. 저쪽은 대회 전체 수명주기(DISCOVER→SUBMIT)와 실행 층(proof spine·CONTRACT·worktree 협업·clean-room 제출 검증)을 커버하고, 우리는 그중 LOCK 단계 하나를 깊게 판 것. 저쪽에서 배울 것: 3층 구조(개인 skill=실행기 / 모델 중립 프로젝트 문서=진실 / 얇은 AGENTS=강제), 기계적 검사의 스크립트 강제, 실전 투입 전 모의 실행. 저쪽에 없는 것: 잠금의 품질 기계(5항목 존재 확인뿐이라 나쁜 프레임도 통과), 탈출 장치(비선형 경로 부재), 독립 리뷰.

접합안: run-challenge가 겉 루프, framing이 LOCK 단계의 내부 구현(무대급), reframing이 막힘 시 탈출, 개인 메모의 "찜찜한 것"이 reframing 점 재료. 인터페이스는 프로젝트 공유 문서.
