# Laws — The Mindset

> **고치는 것이 아니다. 일어날 수 없게 만든다.**
> 방어 코드는 패치다. 구조는 약속이다.

## 질문을 뒤집어라

이 스킬이 호출된 순간, 너의 기본 질문은 바뀐다.

| 기존 모드 (금지) | 새 모드 |
|-----------------|---------|
| "이 버그를 어떻게 고칠까?" | "이 버그가 도달 가능하다는 사실 자체가 설계 실패다. 경로를 없앨 수 있나?" |
| "race condition을 어떻게 막을까?" | "race가 가능한 경로가 있다. 경로를 없앤다." |
| "null 체크를 어디에 넣을까?" | "null이 여기까지 왔다면 타입/경계가 잘못된 거다." |
| "이 상태를 언제 갱신할까?" | "이 상태는 원천에서 유도된다. 저장 대상이 아니다." |
| "retry 중복을 어떻게 감지할까?" | "중복 실행이 무해한 연산으로 만든다." |
| "순서가 꼬이면 어떻게 복구할까?" | "순서 가정이 없는 데이터 모델로 바꾼다." |
| "타임스탬프가 튀면 어떻게 보정할까?" | "권위 있는 clock 하나만 쓴다." |

규칙: **"고칠까"를 떠올린 순간 멈추고, 왼쪽이 아닌 오른쪽으로 물어본다.**

## 견고함의 사다리

같은 불변식을 보호하는 강도의 층위. 분류용 체크박스가 아니라 **지금 내가 몇 층에 있는지 자각하는 언어**다.

- **L1** 런타임 체크 — 호출자가 까먹으면 뚫린다
- **L2** 테스트 — 안 쓴 경로는 못 잡는다
- **L3** 타입 — 컴파일이 막는다
- **L4** 불변식 강제 — 저장소/경계가 막는다 (unique, atomic, FSM)
- **L5** 표현 불가 — 잘못된 상태가 존재할 수 없다

내 수정이 어느 층에 머무는지 의식한다. 한 층 위가 보이면 그쪽을 먼저 의심한다. **L5가 항상 옳은 것은 아니다** — 하지만 L1에 머무는 이유를 자신에게 설명할 수 있어야 한다.

## 견고한 사고의 어휘

참조용. 분류 강제가 아니라, 사고할 때 떠올릴 단어들이다.

### Invalid states unrepresentable
- 여러 곳의 null 체크 = 타입 경계가 잘못됐다 → 경계에서 1회 파싱, 내부는 non-null
- optional 난무하는 상태 객체 = sum type이 부족하다 → discriminated union
- 음수/빈값/잘못된 ID가 흐른다 = smart constructor / branded type / NonEmpty가 없다
- "초기화 전 사용" = phantom type으로 state가 구분돼야 한다

**원칙**: *Parse, don't validate*. 경계에서 파싱 → 내부엔 올바른 타입만 흐른다.

### Race-free 사고
- TOCTOU (check 후 use 사이 변경) = atomic primitive가 없는 자리
- Lost update (동시 write) = version / single writer가 없는 자리
- Retry 중복 = idempotency key가 없는 자리
- Out-of-order delivery = sequence / causal token이 없는 자리
- 시계 비교로 "최신" 판단 = 권위 있는 clock이 없는 자리
- Interleaved state transition = FSM + 원자 전이가 없는 자리

**원칙**: atomic boundary를 application code가 아니라 storage/transport primitive에 맡긴다 (DB unique, CAS, row lock, message ack, file rename).

### SSOT & derive
- 저장된 파생값은 반드시 drift 한다 → 계산 가능한 것은 저장하지 않는다
- 동기화 코드가 필요하면 SSOT가 둘 이상이다 → 하나로 줄인다
- 상태를 납작하게 저장하면 동시수정 경로가 생긴다 → 이벤트 append-only
- 한 엔티티는 한 곳에서만 write (single writer), 읽기는 어디서든

### Single control point
- 한 기능의 타이밍/상태 관리가 2곳 이상에 퍼져 있다 = 동기화 필요 = 버그 필연
- 한 곳이 흐름 전체를 소유하고, 나머지는 props/callback으로 수동 참여

## 내면의 대화

체크박스 대신 **말로 설명한다**. 아래 문장이 자연스럽게 나오지 않으면 아직 마인드셋이 전환되지 않은 것이다.

- "이건 L1에 머물러 있어. 원본 경계를 여기로 옮기면 L3로 올라가."
- "이건 race인데 app-level lock을 박으려 했어. DB unique로 옮기면 경로 자체가 사라져."
- "이 파생값이 저장돼서 drift가 났어. 유도 쿼리로 바꾸면 저장이 필요 없어."
- "이 null 체크 3개는 경계가 잘못된 증거야. 파싱을 여기로 올리면 내부에선 null이 존재하지 않아."
- "이 retry 로직은 idempotency key 없이 '아마 안전'에 기대고 있어. key 하나 박으면 가정이 사라져."
- "이 타이밍 로직이 4곳에 흩어져 있어. 한 곳이 흐름을 소유하면 동기화가 필요 없어."

**금지어**: "거의 안 일어남", "일단 가드 추가", "여기서도 체크 하나 더", "아마 괜찮음", "나중에 다시 보자".

## 탐색 우선

마인드셋이 바뀌었다고 해서 결론을 서두르면 안 된다. 불완전한 정보로 구조를 뒤엎는 건 더 큰 실패다.

- 경로 전체를 읽고 원천을 찾는다
- 경계가 어디인지 먼저 식별한다
- 그 다음에야 한 층 위로 올릴 방법을 상상한다
