# Combined intent and team proposal

*Lead. Adapt this to the user's language and tone. This is a message shape, not a new
file to create per run or a checklist to ask the user to fill. Keep the exact intent
revision, source references and model/effort values in the existing mission/brief.*

Explain what you learned, recommend a direction, describe the user-visible result and
what stays unchanged, and say how completion will be checked. Then name each selected
model and its responsibility in ordinary language. Include remaining material choices
only when there are any, with your recommendation and its practical trade-off. Ask for
one confirmation covering the intended result and team. Wait before staffing.

Illustrative Korean message for a document-cleanup request:

> 현재 문서를 살펴보니 같은 주제를 여러 파일이 현재 기준처럼 설명하고 있어.
> 기존 문서 중 하나를 기준으로 정하고, 다른 문서의 유효한 내용만 합치는 방향을 추천해.
> 끝나면 각 주제에서 어느 문서를 읽어야 하는지 바로 알 수 있게 만들 거야.
> 코드 동작은 바꾸지 않고, 고유한 정보가 남은 문서는 임의로 지우지 않을게.
> 정리 후에는 참조가 끊기거나 서로 다른 기준이 남아 있는지 확인할 거야.
>
> 팀은 <선택한 모델>이 문서 관계를 조사하고 정리까지 맡고,
> <선택한 모델>이 원본과 비교해서 빠진 정보나 모순이 없는지 독립적으로 확인하도록 할게.
> 나는 정리 기준과 최종 결과를 맡을게.
>
> 이 작업 방향과 팀 구성으로 진행해도 될까?

Only when an actual choice remains, add a concrete line before the confirmation:

> 중복 문서는 당장 삭제하지 않고 과거 자료라고 표시해서 분리하는 쪽을 추천해.
> 검색 결과는 줄이면서도 이전 설명을 바로 비교할 수 있어서야. 이 방식까지 포함해서
> 진행할지, 중복 문서는 삭제할지만 정해줘.

The fictional findings above must be replaced by actual evidence. Do not report an
inspection you did not perform. Do not add an unnecessary choice to imitate the example.
No technical acronyms, opaque IDs, file inventories or implementation jargon are needed
in the approval message unless the user requests that detail. Preserve material behavior,
cost and permission information even when keeping the wording simple.
