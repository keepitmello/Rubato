## 비용 분석에서 바로잡은 부분

문맥을 비우는 함수 자체에는 모델 호출이 없지만, 그 전에 노트를 생성하는 요청과 저장 완료를 확인하는 왕복, 새 창에서 노트를 읽는 요청에는 비용이 있어요. 새 계산기는 이 세 단계를 기본 비용에 넣어요. 원문 검색이 0인 시나리오도 노트 읽기까지 0원으로 처리하지 않아요.

기존 방식의 기준도 하나가 아니에요. 센피의 OpenAI 직접·코덱스 경로에는 원격 압축 연결이 있고, 루바토의 페이블 경로에는 앤트로픽 서버 압축이 있어요. 둘 다 무조건 일반 텍스트 요약 5천 토큰으로 간주하면 안 돼요. 서버 압축의 사용량과 불투명한 압축 항목의 실제 토큰 수는 기록 또는 실제 요청에서 보정해야 해요.

이전 대화에서 나온 “페이블 18%/27%가 최적”, “원문 10~15K가 손익분기” 같은 숫자는 검증된 운영 권고가 아니에요. 재현 가능한 실제 기록과 완전한 비용식으로 확정한 값이 아니므로 이번 구현의 기본값이나 합격 기준에 채택하지 않았어요.


OpenAI 원격 압축의 재전송 경로도 확인했어요. 참고 센피 소스의 `latestRemoteCompaction`은 가장 최근 압축 항목이 원격 압축 형식이 아니면 더 옛 항목을 찾지 않고 종료해요. 따라서 새 창 경계 뒤에 이전 원격 압축 항목을 다시 넣는 것으로 코드를 해석하지 않아요. 다만 설치본에서 같은 동작인지와 최종 요청 본문은 여전히 로컬 검증 대상이에요.

## 아직 검증해야 하는 부분

독립 테스트는 실제 SQLite와 파일 저장을 사용하지만 에이전트 실행 절차는 시험용 객체로 검사해요. 고정된 설치 패키지 전체, 실제 모델 요청, 장기 작업의 상태 유지, 터미널·원격 화면은 로컬 검증이 남아 있어요. 설치된 엔진에서 경계 직전 검사 위치가 다른 경우 억지로 문자열을 맞추지 말고 의미가 같은 위치인지 확인해야 해요.

입력 토큰의 예비 계산은 UTF-8 바이트 기반 추정이에요. 모델별 토큰 분할, 이미지, 공급자 내부 지침을 완벽히 알지 못해요. 실제 사용량을 우선 참고하되 최종 입력 허용을 수학적으로 보장한다고 주장하지 않아요. 한도 초과 시 요약이나 삭제로 돌아가지 않는 점은 유지해요.

전체 기록을 다시 읽는 비용은 기록 길이에 따라 늘어요. 초장기 세션의 메모리·디스크·지연 측정은 별도로 해야 해요. 데이터베이스를 다시 만들면 원문과 노트는 복구하지만 파생 진단 이력까지 되살리지는 않아요.
