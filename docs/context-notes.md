# 작업 노트와 원문으로 문맥을 이어가기

이 기능은 같은 세션에서 모델에게 보내는 활성 대화만 새 창으로 바꿔요. 세션 식별자, 작업 폴더, 파일, 작업자는 새로 만들지 않아요. 이전 대화는 저장소에 남고, 현재 모델이 작업 노트를 쓰고 필요할 때 원문을 찾아와요.

## 노트와 창 전략

작업 노트와 원문 기록은 모든 모델이 써요. 창을 어떻게 끝낼지만 모델마다 달라요. 노트는 창이 끝나기 직전에 쓰는 요약이 아니라, 언제 창이 끊겨도 이어갈 수 있게 평소에 갱신하는 작업기억이에요.

| 모델 | 창 전략 | 자동 전환 | 선 |
|---|---|---|---|
| Codex 전체 (`openai-codex/*` — 솔·테라·루나·아스트라, `-sub` 포함) | 노트 전환 | 있어요 | 안내 목표-6,144, 목표 90%, 하드 95%. 같은 레인·같은 272K 창이라 한 전략이에요 |
| 그록 4.7 (`xai`, `cursor`) | 노트 전환 | 있어요 | 소프트 300K, 목표 320K, 하드 400K. 200K 가격 경계에서는 자르지 않아요 |
| 클로드 페이블 5.1·오퍼스 5.5·소네트 5 (`anthropic`, `-sub` 포함) | Anthropic 서버 컴팩션 | 없어요 | 서버 컴팩션 trigger = 비상선 |
| 딥시크, 제미나이, 하이쿠, 그 밖의 모델 | 비상선만 | 없어요 | 비상선에서만 체크포인트 뒤 전환 |

- **비상선**은 `창 - 출력 예약 - 여유분`이에요. 출력 예약은 Pi의 응답 예약(`reserveTokens` 기본 16,384)을 창의 4%까지(최대 49,152) 늘리고 모델 최대 출력을 넘지 않게 한 값, 여유분은 창의 2%(최소 8,192)예요. 창 1,000,000이면 940,000이에요. 모델 카탈로그의 최대 출력(딥시크 384K)을 그대로 빼지 않아요. 요청의 `max_tokens`는 엔진이 남은 창에 맞춰 줄여요.
- **소프트 구간**(그록 300~320K)에서는 노트가 최신인 채로 턴이 끝나면, 즉 모델이 방금 노트만 저장했으면 그 경계에서 새 창으로 넘어가요. 작업 중이면 그대로 둬요.
- **목표선부터**는 노트 갱신과 `new_context`만 하는 구간이에요. 노트가 최신이면 턴 경계에서 바로 넘어가고, 아니면 체크포인트 전용 턴을 요청해요. 하드선에 닿아도 먼저 체크포인트 턴을 요청하고, 그 턴이 두 번 실패했을 때만 마지막 노트로 넘어가요.
- **클로드**는 Rubato 쪽 자동 컴팩션도, 노트 기반 자동 전환도 쓰지 않아요. 자동 임계점은 없고, Anthropic 서버 컴팩션은 비상선에서만 돌아요. `trigger`를 빼면 꺼지는 게 아니라 Anthropic 기본값 150,000에서 돌기 때문에, 비상선을 계산할 수 없으면(창을 모르면) 서버 컴팩션 설정 자체를 붙이지 않아요.
- **모델이 부르는 `new_context`와 `/new-context`**는 모든 모델에서 쓸 수 있어요.

선은 `harness/rubato-pi/src/context-budget.mjs` 한 곳에서 계산해요. 노트 관리자와 서버 컴팩션 와이어가 같은 파일을 써요.

## 노트 갱신 안내

마지막 노트(또는 마지막 안내) 뒤로 창의 20%만큼 문맥이 쌓이면 노트 갱신 안내를 한 번 붙여요. Codex 272K면 54,400, 그록 500K면 100,000, 1M 모델이면 200,000이에요. 안내는 "상태가 실질적으로 바뀌었으면 갱신하라"는 권고라서, 바뀐 게 없으면 모델은 그대로 계속해요. 쌓인 양은 응답마다 모델이 보고한 문맥 크기의 증가분을 더해서 세요. 서버 컴팩션으로 문맥이 줄어도 그동안 한 작업은 사라지지 않아요.

안내는 기존 마지막 안내와 같은 방식으로 붙어요. 기록된 순간의 마지막 메시지 바로 뒤에 고정 문구로 들어가고, 그 뒤 모든 요청에서 같은 자리에 있어요. 이전 메시지·안내·도구 정의의 위치나 내용을 바꾸지 않으니 캐시 접두가 깨지지 않아요. 새 창에는 이전 창의 안내가 따라가지 않아요.

이벤트 기반 안내(설계 확정, 큰 실패, 하위 작업 완료, 인수인계 등)는 코드에 싸고 분명한 신호가 없어서 넣지 않았어요. 모델 변경은 신호가 있지만 바뀐 뒤에야 알 수 있어서, 이전 모델이 노트를 쓸 기회가 없어요.

## 실행 모드

```sh
# 작업 노트: 모든 모델의 기본값이에요.
RUBATO_CONTEXT_MODE=history-notes node harness/rubato-pi/bin/rubato-pi.mjs

# 기존 요약: 명시했을 때, 이미 요약으로 기록된 세션, 외부 실행기가 문맥을 소유하는 연결에서만 써요.
RUBATO_CONTEXT_MODE=summary node harness/rubato-pi/bin/rubato-pi.mjs
```

`RUBATO_CONTEXT_MODE`를 사용자가 정하면 그대로 씁니다. 없으면 세션의 모드 기록이나 작업 노트 창을 따르고, 둘 다 없으면 작업 노트로 시작해요. `claude-sdk-oauth`처럼 외부 실행기가 대화를 소유하는 연결만 요약으로 시작해요. 부모 세션이 고른 모드는 자식 프로세스에 이어지지 않아요.

이미 요약으로 기록된 세션은 그대로 요약으로 열려요. 그런 세션에서 모델을 고르면 작업 노트로 바꿀지 한 번 물어요. 요약에서 작업 노트로의 전환은 언제든 가능하고, 이미 새 창을 만든 세션은 요약으로 되돌리지 않아요. 확인을 거절하면 같은 모델 쌍에 대해 다시 묻지 않아요.

이미 새 창을 만든 세션은 `history-notes`로 다시 열어야 해요. 그 기록을 기존 방식으로 열면 복구 도구가 없는 채 진행하지 않도록 오류로 막아요. 이전 버전의 기록 형식은 유지했고, 새 변환 코드의 표식만 두 번째 버전으로 구별했어요.

## 설정

| 설정 | 의미 |
|---|---|
| `RUBATO_CONTEXT_WINDOW_TOKENS` | 노트 전환 모델의 목표선을 낮추는 실험용 값이에요. 선을 올리지는 않아요. |
| `RUBATO_CONTEXT_REMINDER_TOKENS` | 소프트선(Codex는 목표선)에서 이만큼 앞에 마지막 안내를 해요. 기본 6,144예요. |
| `RUBATO_CONTEXT_NOTE_NUDGE_RATIO` | 노트 갱신 안내 간격(창 대비 비율)이에요. 기본 0.2, 0이면 꺼요. |
| `RUBATO_CONTEXT_OUTPUT_RESERVE_TOKENS` | 비상선 계산의 출력 예약을 직접 정해요. |
| `RUBATO_CONTEXT_SAFETY_MARGIN_TOKENS` | 비상선 계산의 여유분을 직접 정해요. |

```sh
# 동작 확인용 작은 창이에요. 비용 최적 설정으로 취급하지 않아요.
RUBATO_CONTEXT_MODE=history-notes RUBATO_CONTEXT_WINDOW_TOKENS=24000 \
  node harness/rubato-pi/bin/rubato-pi.mjs
```

큰 도구 결과로 선을 갑자기 넘으면 원문을 보존한 채 멈출 수 있어요. 출력 공간과 토큰 추정 오차가 있으므로 목표가 곧 실제 요청 크기는 아니에요.

마지막 안내 내용과 삽입 위치는 창마다 한 번만 기록해요. 이후 토큰 수가 달라져도 이전 안내를 바꾸지 않아요. 숫자가 필요하면 잔여 예산 도구를 호출해요. 안내 위치를 복원할 수 없으면 캐시를 위해 임의로 옮기지 않고 중단해요.

## 도구 계약

| 도구 | 역할 |
|---|---|
| `history_list_windows` | 현재 가지의 창 목록과 항목 수를 보여줘요. 빈 중간 창도 포함해요. |
| `history_list_items` | 창 안의 항목을 짧은 미리보기로 나열해요. |
| `history_search_contents` | 대소문자를 구분하는 문자열 검색을 해요. |
| `history_read_item` | 원문을 문자 범위로 읽어요. 지원하는 이미지 한 개를 다시 넣는 선택지도 있어요. |
| `notes_list_files_by_prefix` | 가상 노트 목록을 접두사로 찾아요. |
| `notes_read_file` | 노트를 줄 또는 문자 범위로 읽어요. |
| `notes_search_contents` | 노트에서 문자열을 찾아요. |
| `notes_append_to_file` | 기존 노트 끝에 덧붙여 새 판본으로 저장해요. |
| `notes_write_file` | 노트의 새 판본을 저장해요. |
| `new_context` | 현재 도구 묶음이 끝난 뒤 새 창으로 넘어가도록 예약해요. |
| `get_context_remaining` | 현재 예산과 추정 사용량을 읽어요. |

도구는 모델에 직접 노출해요. 자동 생성한 요약 인수를 `new_context`에 넣지 않아요. `/new-context`는 사용자가 요청하는 전환 명령, `/context-status`는 상태 확인 명령이에요. 수동 전환에도 최신 노트가 필요해요.

노트 경로는 실제 파일 경로가 아니에요. `work/current.md`와 `/root/notes/work/current.md`는 같은 현재 세션 노트를 가리켜요. 상위 경로 이동, 다른 세션 이름을 사용한 조회는 허용하지 않아요. 파일명은 최대 512 UTF-8 바이트, 노트 한 개는 최대 1,000,000바이트예요.

목록·검색 결과가 잘리면 반환된 이어보기 위치를 사용해요. 노트 목록은 `after_path`, 창 목록은 `after_window_id`, 원문 항목 목록은 `after_item_id`를 사용해요. 노트 검색은 `next_after_path`로 다음 파일을 찾고, 파일 안에 더 많은 결과가 있으면 `next_start_line`부터 노트를 읽어요. 긴 한 줄은 `offset_chars`로 이어 읽어요. 문자 범위는 유니코드 문자 기준이에요.

## 전환 순서

1. 현재 모델이 목표, 결정, 실패 이유, 현재 진행, 다음 단계와 중요한 원문 위치를 노트에 저장해요.
2. 기존 세션 작성자가 노트 항목을 파일에 저장했는지 확인하고 동기화해요. 검색용 저장소에도 반영해요.
3. `new_context` 호출은 예약만 해요. 같은 묶음에 아직 실행되는 도구가 있으면 중간에 자르지 않아요.
4. 묶음이 끝나면 최신 노트인지, 새 사용자 입력이나 작업 결과가 생겼는지 검사해요.
5. 준비 항목을 저장하고 센피의 `applyCompaction`으로 경계를 적용해요. 실제 저장 직전에도 현재 끝 항목과 취소 상태를 재검사해요.
6. 새 입력에는 창 식별자와 작은 노트 목록만 넣어요. 노트 본문과 과거 원문은 모델이 다시 읽어요.

엔진의 내부 `compaction` 필드·이벤트는 경계를 운반하는 데 사용해요. 이 이름이 나타난다고 새 방식에서 모델 요약을 실행한 것은 아니에요. 실행 여부는 모델 요청과 내용으로 판단해요.

## 실패와 다시 열기

노트 뒤에 실제 작업이 더 진행됐으면 전환하지 않아요. 현재 모델이 새 결과를 반영한 노트를 다시 쓰면 돼요. 관리용 도구 왕복만 뒤따른 경우에는 전환할 수 있어요. 이 검사는 노트의 의미 품질까지 평가하지 않아요.

`eval`을 통해 노트를 관리해도 같은 규칙을 적용해요. 실행 기록에 노트·원문 관리 도구만 있고 셀과 모든 호출이 정상 완료돼야 관리용 왕복으로 인정해요. 실제 작업 도구가 섞이거나 기록이 불완전하면 전환하지 않아요. `eval` 안의 `new_context`는 예약만 하고, 바깥 호출이 끝난 뒤와 경계를 저장하기 직전에 다시 검사해요.

턴 경계에서 노트가 최신이 아니거나 체크포인트 턴이 노트를 완성하지 못하면, 대화를 버리거나 곧바로 실행을 중단하지 않고 같은 모델에 한 번 갱신을 요청해요. 갱신에도 실패하거나 문맥에 안전한 여유가 없으면 원문을 보존한 채 멈춰요. 저장 실패는 이 재시도 대상이 아니며, 사용자가 취소한 실행도 다시 시작하지 않아요.

경계를 저장하기 전에 실패하면 과거 문맥을 유지해요. 경계가 저장된 뒤 엔진 후처리가 실패하면 현재 실행에서 계속 모델을 호출하지 않아요. 같은 세션을 다시 열어 저장된 경계를 기준으로 복구해요. 사용자가 취소한 작업을 이 기능이 자동으로 다시 시작하지 않아요.

저장 실패가 발생한 실행에서 `/new-context`를 반복해 억지로 넘기지 않아요. 디스크 상태를 먼저 복구하고 세션을 다시 열어요. 자동 요약이나 긴급 원문 삭제로 실패를 숨기지 않아요.

SQLite는 `agentDir/context-notes/<세션식별자 해시>.sqlite`에 있어요. 노트와 원문을 복구하는 원본은 기존 세션 파일이에요. 검색 저장소를 재생성할 때는 루바토를 먼저 종료하고 SQLite 및 보조 파일을 함께 백업한 뒤 치워요. 다시 열면 현재 가지의 원문·노트를 복원해요. 진단 이력은 파생 자료라 사라질 수 있어요.

## 지원 범위와 검증

외부 실행기가 대화와 요약을 소유하는 `claude-sdk-oauth` 경로는 작업 노트 창을 관리할 수 없어서 요약으로 시작하고, 작업 노트 모드로 열면 거부해요. 다른 중계 경로도 실제로 자체 요약·삭제가 섞이는지 확인하기 전에는 동일한 실험으로 간주하지 않아요.

독립 테스트와 실제 엔진 검증은 구분해요. `IMPLEMENTATION_HANDOFF.md`의 설치본 검사와 `docs/context-notes-behavior-guide.md`의 요청 확인을 마친 뒤 로컬 적용을 완료로 판단해요. 이번 검토 내용은 `docs/context-notes-review.md`, 비용 비교는 `docs/context-cost-simulation-guide.md`에 있어요.
