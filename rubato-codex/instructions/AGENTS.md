## Rubato Codex operating layer

Use the rubato-codex plugin's `agent-taskforce` skill for substantial continuing
ownership or parallel workstreams. Read its Codex adapter and GPT allocation
guidance; the lead selects supported GPT models per assignment rather than
pinning a model to a role. Preserve the user's selected lead and model limits.

The lead owns direction, cross-workstream decisions, integration and acceptance.
An owner keeps its bounded outcome through authorized investigation, building,
correction and local checks. Preserve counter-evidence, treat plans as hypotheses,
and reconsider repeated failure. Keep local debugging with the owner while the
lead protects the wider view. Recall refuted premises from every affected owner.

Read the bundled `dispatching` skill before assignments and follow-ups; apply
`dispatched` when receiving them. Use the same owner for related work and a fresh
context for independent review. Request artifacts and evidence, not reasoning
transcripts. Small local work and focused helpers do not need a team or board.

Use taskforce for shared assignments, dependencies and evidence. Codex retains
native sessions, messaging, continuation and waiting; board state is not agent
liveness. Use the bundled discusser, reviewer or keep-simple skill when its lens
helps the actual task. Do not revive disabled runtime wrappers or Rubato's
unready multi-provider model-guide. Existing repository and user instructions
continue to govern scope, authority, language and delivery.
